## 사용

1. MS Forms로 들어온 아이디어는 자동으로 접수됩니다. 직접 접수하려면 목록의 **직접 접수**에서 작품명을 입력합니다. 처음이라면 공유 우산 또는 상담 개선 합성 예제를 선택할 수 있습니다.
2. 캡처 이미지나 문서 파일(PDF·Word·PowerPoint·Excel)을 올립니다. 캡처를 눌러 크게 본 화면에서 **이 쪽 다시 캡처**를 누르면 원본 문서에서 그 쪽만 다시 받아 바꿔 끼우고(올린 문서는 데이터 폴더에, MS Forms 첨부는 OneDrive 작품 폴더에 있습니다), **캡처 삭제**로 그 장만 지웁니다. 문서는 서버가 열어 쪽마다 캡처로 접수합니다(MS Forms 첨부와 같은 방식). PDF는 PDFKit으로 바로 바꾸고, MS Forms 첨부 PDF는 모두 보호 문서로 보고 Edge가 있으면 처음부터 Edge로 엽니다(직접 올린 PDF는 맥 PDFKit으로 먼저 읽고, 못 열거나 '보호된 문서' 안내 쪽만 보이는 겉 PDF면 Edge로). 보호(MIP) PDF는 회사 계정으로 로그인한 Microsoft Edge의 새 창에 열어 먼저 '다른 이름으로 저장'(⌘S)한 사본을 읽습니다(저장 권한이 있는 문서는 사본이 열려 원본 화질로 나오고, 사본은 읽자마자 지웁니다). 저장이 안 되거나 사본도 보호되어 있으면 쪽마다(`#page=N&view=FitV`, 쪽 높이를 창에 맞춤) 열어 그 창을 캡처하고, 탭·주소창·회색 여백을 잘라 쪽만 남긴 뒤 창을 닫습니다(같은 화면이 다시 나오면 마지막 쪽). Word도 창을 캡처한 뒤 리본·눈금자·상태 표시줄·회색 여백을 잘라 쪽만 남깁니다. Edge가 없으면 Adobe Acrobat Reader로 열어 ⌘0(페이지 맞춤) → 첫 쪽 → → 키로 넘깁니다. **윈도우**에서는 앱 창을 화면에 띄우지 않습니다(사람이 함께 쓰는 업무 PC). PDF는 Windows 기본 PDF 기능으로 바꾸고, Word·PowerPoint·Excel은 Office 앱을 창 없이 열어(COM) PDF로 내보낸 뒤 같은 방식으로 바꿉니다(내보낸 PDF는 읽자마자 지움). 보호 문서는 내보낸 PDF도 보호되므로, MS Forms 첨부와 함께 **이 앱 전용 Edge 프로필**을 창 없이(헤드리스) 열어 쪽마다 화면을 받아 쪽만 잘라 냅니다(Edge 개발자 프로토콜, 파이프). 그 프로필에는 처음 한 번 `deploy/edge-login.bat`으로 회사 계정에 로그인해 둡니다(회사 PC가 윈도우 계정으로 자동 로그인되면 필요 없을 수 있음). 문서 권한이 내보내기·화면 표시를 막거나 회사 정책이 Edge 원격 디버깅을 막으면 읽지 못하고 까닭을 보여 줍니다. 회사 뷰어에서 캡처가 허용된 화면을 이미지로 추가할 수도 있습니다. 파일 선택·드롭·붙여넣기 또는 브라우저의 문서 창 공유를 사용합니다. Windows·VDI에서 만든 PNG/JPG/WebP는 회사가 허용한 전달 경로로 가져옵니다. 창 공유 중에는 ‘현재 화면 추가’를 누른 순간만 저장합니다.
3. PDF·Word는 쪽, PPT는 슬라이드, Excel은 시트·범위별로 묶습니다. 캡처를 누르면 중앙에 크게 열립니다. 좌우 버튼이나 방향키로 장을 넘기고 Esc로 닫습니다. 그래프 눈금은 있는데 값이 글자로 적혀 있지 않은 쪽은 OCR 배치로 찾아 **도식 검토 추천** 표시를 붙이고, 캡처 탭의 **추천 쪽 도식 검토로 지정**으로 한 번에 지정합니다. 지정하면 다음 요약 때 그 쪽 이미지를 AI에 보내 막대·선 그래프의 값을 눈금에 대어 '약 13.7'처럼 어림해 읽습니다(산점도·좌석도처럼 항목별 값이 없는 그림은 설명만). 다시 요약할 때는 지정·해제한 쪽만 새로 읽고 나머지 요점은 그대로 두므로 작품당 4~5센트 정도 듭니다. 모든 제출 화면을 확인한 뒤 완료를 표시합니다. MS Forms 작품은 첨부를 서버가 캡처하는 동안 직접 올리기 칸을 보이지 않고, 못 읽은 첨부가 있거나 캡처를 모두 지운 뒤에만 보입니다.
4. 작품 화면의 **AI 요약** 단계에서 **요약 만들기**(이미 있으면 작품 머리 오른쪽의 **AI 재요약**)를 누르거나, 전체 작품 목록의 줄마다 있는 **요약** 버튼을 누릅니다. 요약은 Claude Haiku가 원문을 묶음별로 읽어 만듭니다. 요약은 두 묶음입니다. **핵심 요약**은 회사 아이디어 목록의 요약 칸과 같은 모양으로, 맨 위 오렌지색 한 줄에 문서 전체를 한 문장으로 줄인 **한 줄 요약**(목록에는 **제목**)을 두고, 그 아래 **배경**(왜 필요한가) · **내용**(무엇을 어떻게, 굵게) · **효과**(무엇이 좋아지나)를 '~필요', '~제공'처럼 끝나는 개조식으로 씁니다. 핵심 요약 줄에는 쪽 번호를 붙이지 않습니다. 그 아래 **세부 요약**은 같은 문서를 **무엇이 문제인가 → 무엇을 하려는가 → 어떻게 푸는가 → 무엇을 얻었나 → 시사점과 활용** 순서로, 핵심 요약보다 구체적인 대상·절차·수치·조건으로 풀어 씁니다. 각 문장은 연결된 원문과 다시 대조하고, 대조에서 떨어진 물음은 한 번 다시 씁니다. 그래도 원문 근거로 확인되지 않은 물음은 다른 문장으로 메우지 않고 요약 끝에 **비워 둔 항목**으로 알려, 심사자가 원문에서 직접 확인하게 합니다. 세부 요약이 인용한 쪽에 그래프나 표가 있으면 그 부분을 잘라 요점 옆에 최대 3장 붙이고, 누르면 원본 캡처가 중앙에 크게 열립니다. 문장 끝의 쪽 번호(예: 27쪽)는 그 내용이 있는 원문 쪽입니다. 마우스를 올리거나 키보드로 머물면 그 쪽의 인용 부분이 잘린 원문 카드로 떠 인용 줄이 오렌지로 표시되고, 누르면 오른쪽 패널에서 해당 위치를 확인할 수 있습니다. 작품 화면에서는 숫자 1~4로 단계를, J·K로 다음·이전 작품을 넘길 수 있습니다. 전체 작품 목록의 표 위에는 **전체 · AI 요약 · AI 논리점검 · 채점표** 탭이 있어, 같은 작품들을 단계별 결과로 봅니다(왼쪽 메뉴에는 공모전 이름 없이 작품명만 보입니다. 처음 열리는 전체: 핵심 요약 제목·확정 점수, 내용 요약: 핵심 요약의 제목과 '내용', 사실·논리 점검: AI 한마디 평, 채점표: 분야·심사자 평가·확정 점수·1차 결정). 예전 형식(한 줄 요약 → … → 한계, 또는 세부 요약이 결과·근거 → 한계)으로 저장된 요약은 그대로 보이며, **AI 재요약**을 누르면 새 형식으로 바뀝니다(글자 읽기와 요점 추출은 다시 하지 않아 비용이 적게 듭니다). 요약·점검을 실행하는 동안 작품 화면 위에 지금 단계(예: 요점 추출 · 2 / 5, 앞뒤 원문과 오류 후보 재대조)와 0~100% 진행 막대가 보입니다(요약에 이어지는 사실·논리 점검까지 합친 어림 진행률). 요약 아래에는 토큰 사용량과 예상 비용이 표시됩니다.
5. **AI 논리점검**(사실·논리 점검, 다시 하려면 작품 머리의 **AI 재점검**)은 요약을 만들면 이어서 실행됩니다(요약이 있는 작품은 따로 다시 실행할 수 있습니다). AI가 원문 전체를 두 번 독립적으로 훑어 원문 안의 수치·조건·시점 모순, 목표와 실적의 혼동, 인과 비약, 요약이 원문과 다르게 쓴 곳을 찾고, 후보를 원문 앞뒤와 다시 대조합니다. 재대조에서 확정한 것은 **확인 필요**로 보여 주고, 확정하지도 기각하지도 못한 것 중 요약 문장에 대한 것만 **참고**로 접어 둡니다(원문 안의 불확실한 후보는 평가자가 원문을 읽으며 판단합니다). 코드가 재현한 계산 오류는 **계산으로 확인**으로 표시합니다. 사실·논리 점검 탭에는 AI 의견만 보이고, 이 오류 후보 목록은 채점표의 접힌 'AI 사실·논리 점검'에만 남아 있습니다. 요약이 "자료에 ~가 제시되지 않았다"고 쓴 문장은 요약을 마무리하기 전에 원문 전체와 대조해, 원문에 있는 항목은 지웁니다.
6. **채점표**는 점수 없이 의견만 남깁니다. 맨 위 **담당자에게 보내기**로 Slack에 있는 담당자를 검색해 보내면, 그 사람이 DM에 쓴 답장이 **담당자 의견**에 담깁니다. 아래 **검토 의견** 칸에는 직접 의견을 적어 저장합니다. 의견이 하나라도 있으면 목록의 진행 상태가 **의견 받음**이 됩니다.

## MS Forms 공모 연동

공모는 MS Forms로 받고, Power Automate가 응답을 OneDrive 엑셀에 쌓습니다. 첨부는 OneDrive의 Forms 폴더(`Apps/Microsoft Forms/<양식 이름>`)에 들어옵니다. 이 PC에 동기화된 두 곳을 서버가 1분마다 읽습니다. 보호(MIP) 응답 엑셀은 이 PC의 Excel 앱(회사 계정)으로 읽고 고칩니다(윈도우는 화면에 띄우지 않음).

왼쪽 메뉴의 **공모 연동 설정**에서 응답 엑셀과 첨부가 내려받아지는 폴더를 고릅니다. '찾아보기'를 누르면 서버 맥 화면에 macOS 선택 창이 열리고, 이 맥에 동기화된 OneDrive·SharePoint 폴더(`~/Library/CloudStorage/OneDrive…`) 안에서 고를 수 있습니다. 엑셀 열은 회사 Forms 구조(A ID · C 완료 시간 → 인입일 · D 이메일 · E 이름 → 접수자 · G 소속 → 팀 · H 아이디어 제목 → 작품명 · I 간략 설명 · J 첨부 파일명)로 자동으로 읽습니다(`deploy/site.json`의 `forms.columns`, 처음 저장할 때 채움). 저장하면 그 구조로 엑셀을 읽어 보고 '응답 N건 · 첨부 파일 N개'를 보여 줍니다. J열에는 첨부가 최대 5개까지 쉼표·세미콜론·줄바꿈으로 이어 쌓이고, 한글 이름은 `%EA%B8%B0…`처럼 URL 인코딩되어 있어 풀어서 내려받은 파일과 맞춥니다. 이메일과 간략 설명은 작품 머리의 접수 정보 아래에 보입니다.

1. **가져오기**: 응답 엑셀이 바뀌면 새 응답을 작품으로 등록하고, **엑셀에서 지워진 응답은 작품도 지웁니다**(이 기능 전에 엑셀에서 지운 응답도 포함. 캡처·요약·채점표까지 지워지고 되돌릴 수 없습니다. 심사 폴더에 복사한 첨부 파일은 남습니다). 머리글 행도 없는 빈 엑셀이거나 연동 설정에서 다른 엑셀로 바꾼 경우에는 지우지 않습니다. 등록할 때는(작품명·제출일·팀·제출자·분야). 첨부는 `<심사 폴더>/작품/<응답 번호 작품명>/`으로 복사합니다. 첨부가 모두 보호 문서라 내용은 읽지 않고, 요약은 지금처럼 회사 뷰어 캡처로 합니다. 아직 동기화되지 않은 첨부는 다음 확인 때 다시 찾습니다.
2. **심사 배포**(`POST /api/distribute`, 목록 화면 버튼은 없앰): 분야별 담당 심사자마다 `<심사 폴더>/심사자/<이름>/`을 만들고, 배정 작품의 첨부와 `<이름> 평가표.xlsx`를 넣습니다. 평가표에는 항목별 점수 칸(배점 범위 확인), 합계 수식, 실행 규모·1차 결정 목록, 의견 칸이 있습니다. 다시 배포하면 새로 배정된 작품만 더하고 심사자가 적은 값은 그대로 둡니다. 이미 있는 평가표를 읽지 못하면(아직 내려받지 않은 파일·손상·보호 파일) 적은 값을 잃지 않도록 그 심사자의 평가표는 다시 쓰지 않고 알림에 까닭을 보여 줍니다. 공유는 `<심사 폴더>/_공유 요청/<이름>.json`(`name`·`email`·`folder`·`role`)을 남겨 Power Automate가 처리합니다.
3. **평가 모으기**: 평가표가 바뀌면 다시 읽어 목록에 '평가 완료 수 / 배정 수 · 평균', 작품 채점표 탭에 심사자별 점수를 보여 줍니다. 배점을 넘거나 빈 칸이 있으면 '고칠 칸'으로 표시합니다. **채점 결과 받기**에 심사자 평균과 심사자별 총점도 들어갑니다.

### MS Forms 연동 값: `deploy/site.json`의 `forms`

공모 연동 설정에서 고른 값이 이 파일에 저장됩니다. 보통은 화면에서만 바꾸면 됩니다.

`forms` 항목:

| 항목 | 내용 |
| --- | --- |
| `oneDriveRoot` | 이 맥의 OneDrive 폴더. 보통 `~/Library/CloudStorage/OneDrive-<회사 이름>` |
| `formsWorkbook` · `formsSheet` | 응답 엑셀(OneDrive 안의 상대 경로)과 시트 이름(비우면 첫 시트) |
| `columns` | 응답 엑셀의 실제 열 이름: `id`(응답 번호)·`title`(작품명)·`files`(첨부)는 필수, `submittedAt`·`team`·`submitter`·`category`는 선택. 첨부 열은 Forms 파일 업로드 답(JSON) 그대로 또는 파일 이름을 `;`로 나열 |
| `attachmentsDir` | Forms 첨부 폴더(하위 폴더까지 찾음) |
| `reviewDir` | 작품 폴더·심사자 폴더·공유 요청을 만들 심사 폴더 |
| `evaluators` | 심사자 `name`·`email`·`categories`(담당 분야, 응답의 분야 값과 같은 글자). 한 분야에 여러 명 가능 |

열 이름이 틀리면 목록의 '아이디어 공모' 칸에 엑셀에 실제로 있는 열 이름을 보여 줍니다. 시험할 때는 `node scripts/forms-sample.mjs qa-onedrive`로 가짜 OneDrive(응답 3건·첨부·심사자 2명)를 만들고 `forms`를 그 폴더로 맞춰 시험할 수 있습니다.

### AI 연결 (회사망: LiteLLM · Bedrock)

웹앱의 **요약 설정**에서 API 키를 입력합니다. 회사망처럼 LiteLLM 프록시가 Bedrock의 Claude로 연결할 때는 **연결 주소**에 LiteLLM 주소를 함께 넣습니다. 주소를 비우면 Anthropic API에 직접 붙습니다. 모델은 비우면 Haiku 5.5(`claude-haiku-5-5`)이고, LiteLLM에 다른 이름으로 등록돼 있으면 그 이름을 적습니다.

- 저장할 때 그 키와 설정으로 모델을 쓸 수 있는지 확인하고, 맞을 때만 저장합니다. LiteLLM은 모델 목록(`/v1/models`)에 그 모델이 있는지 봅니다. 서버 재시작은 필요 없습니다.
- 키는 이 맥의 사용자 전용 설정(`~/Library/Application Support/ContestReviewDesk/`)에 저장되고 화면에 다시 보이지 않습니다. 처음에는 어느 브라우저에서든 등록할 수 있고, 그 뒤로는 등록한 브라우저나 지금 키를 아는 사람만 바꿀 수 있습니다.
- 요청은 LiteLLM의 Anthropic 형식 엔드포인트(`<연결 주소>/v1/messages`)로 보내고, 키는 `Authorization: Bearer`와 `x-api-key`로 함께 보냅니다. LiteLLM이나 Bedrock이 구조화 출력·생각 깊이 옵션을 거절하면 자동으로 JSON만 요청하는 방식으로 바꿔 다시 보냅니다.
- 비용은 응답의 토큰 수에 Haiku 5.5 공개 단가를 곱한 추정입니다. LiteLLM 연결에서는 Anthropic 집계와 대조하지 않으니 실제 사용량은 LiteLLM 사용량 화면에서 확인합니다.

### 회사망에 붙일 때 확인할 것

- **OneDrive 동기화**: Forms 첨부 폴더와 심사 폴더는 Finder에서 '항상 이 기기에 유지'로 둡니다(클라우드 전용 파일은 읽을 때마다 내려받습니다).
- **암호화 레이블**: 첨부는 보호된 채 복사합니다. 응답 엑셀과 심사자 평가표에 암호화 레이블이 붙어 있으면 맥의 Excel 앱(회사 계정)으로 읽습니다. 다만 보호된 평가표에는 새 작품을 덧붙이지 않으므로(다시 쓰면 보호가 풀림), 평가표는 암호화 없는 레이블로 두거나 해당 폴더를 자동 레이블 대상에서 빼는 것이 좋습니다.
- **AI 연결**: 요약 설정에서 LiteLLM 주소와 API 키를 넣습니다. LiteLLM 주소가 사내 주소라 바깥 프록시가 필요 없으면 다음 항목은 건너뜁니다.
- **프록시**: 회사망에서 AI 주소로 나갈 때 HTTP 프록시가 필요하면, `HTTPS_PROXY`(필요하면 `NO_PROXY`)를 설정한 터미널에서 `python3 deploy/start-web.py`를 실행합니다. 서비스에 프록시 설정이 함께 들어갑니다(Node의 `NODE_USE_ENV_PROXY=1`).
- **접속 코드**: 웹앱은 지금 로그인 없이 열려 있어서, 주소를 아는 사람은 누구나 작품과 채점표를 고칠 수 있습니다. 회사망에서는 `deploy/change-access-code.command`로 접속 코드를 켜는 것을 권합니다.

### Power Automate: 심사자 폴더 공유 흐름

Forms → 응답 엑셀 흐름과 별개로 하나 더 만듭니다. 동작 이름은 한국어 화면 기준이고, 괄호는 영어 이름입니다.

1. 트리거: OneDrive for Business **파일이 생성되는 경우(속성만)** (When a file is created (properties only)). 폴더는 `/<심사 폴더>/_공유 요청`.
2. **파일 콘텐츠 가져오기** (Get file content) → **JSON 구문 분석** (Parse JSON). 스키마는 `name`·`email`·`folder`·`role` 네 개의 문자열입니다.
3. SharePoint **경로를 사용하여 폴더 메타데이터 가져오기** (Get folder metadata using path). 사이트 주소는 내 OneDrive 주소(`https://<회사>-my.sharepoint.com/personal/<계정>`), 폴더 경로는 `/Documents` 뒤에 JSON의 `folder`를 붙인 값입니다.
4. SharePoint **항목 또는 폴더에 대한 액세스 권한 부여** (Grant access to an item or a folder). 목록 이름은 `Documents`, ID는 3의 ItemId, 받는 사람은 JSON의 `email`, 역할은 '편집 가능'으로 합니다. 초대 메일을 보내려면 알림을 켭니다.
5. OneDrive for Business **파일 이동** (Move or rename a file). 요청 파일을 `/<심사 폴더>/_공유 요청/완료/`로 옮기고, 같은 이름이 있으면 덮어씁니다. 대시보드는 '완료' 폴더의 파일을 보고 공유 상태를 '공유 완료'로 바꿉니다.

## 요약 모델과 비용

요약 모델은 Claude Haiku 5.5(추출 low · 판단 medium) 하나입니다. 왼쪽 메뉴 **요약 설정**의 ‘AI 사용량 확인’ 표는 Haiku 실행을 하나도 빠짐없이 기록해 최근 7일(UTC) 날짜별 실행 수·토큰·추정 비용을 보여 줍니다. 비용은 API 응답의 사용량에 공식 단가(입력 $0.10, 출력 $0.50, 캐시 읽기 $0.01, 캐시 쓰기 $0.125/$0.20 per MTok, 프롬프트 10만 토큰 초과 시 5배)를 곱한 값입니다. 조직용 Admin 키로는 Anthropic이 집계한 토큰과 자동으로 대조하고, 그렇지 않으면 Claude Console의 Cost 화면에서 같은 날짜(UTC) 금액과 비교합니다. 맥 앱에 API 키를 붙여넣어 저장하면 사용자 전용 앱 설정에 보관합니다. 공개 웹 앱에서 AI 요약을 실행하면 서버에 등록된 키를 자동으로 사용하며 사용료는 등록 계정에 청구됩니다. 키 교체는 맥 앱이나 키 관리 권한이 있는 브라우저에서 할 수 있습니다. AI 요약은 OCR 텍스트와 도식 검토로 지정한 캡처를 Anthropic에 전송합니다. 해당 요약의 사실·논리 점검에도 같은 Haiku를 사용합니다.

AI 결과에는 이번 실행의 일반 입력, 출력, 캐시 읽기·쓰기, 총 토큰과 예상 달러 비용이 표시됩니다. 요약과 사실·논리 점검을 따로 집계하며 출력 제한으로 재시도한 응답도 포함합니다. 예상액은 요청별 Anthropic 공개 단가를 적용한 값입니다. 기록 기능 도입 전 결과는 사용량 미기록으로 표시됩니다. [공식 요금표](https://platform.claude.com/docs/en/models/haiku-5-5/overview)

## 최초 준비 또는 다른 Mac

Node.js 22.21 이상과 npm을 사용합니다. 글자 인식 엔진과 한국어 가중치는 vendor 폴더에 있습니다. 기본 1600px 판독에서 작은 글씨나 낮은 신뢰도가 발견되면 Kordoc으로 2304px에서 다시 읽습니다. 부호·비교 방향·금액 단위를 포함한 수치가 충돌하거나 정밀 판독에서만 나온 수치는 캡처의 ‘확인이 필요한 숫자’에 위치와 함께 표시합니다. 해당 영역을 확대해 같은 숫자가 다시 읽히면 어느 판독과 일치했는지도 표시합니다. 차트에서 어느 항목의 수치인지 확인할 수 없거나 OCR이 놓친 수식 연산자가 생기면 요약의 ‘도표와 수식 원본 확인’에서 해당 위치를 볼 수 있습니다. Kordoc이 복원한 표는 원본 셀의 좌표와 대조한 뒤 사용합니다. Node 모듈을 포함하지 않은 복사본이라면 인터넷이 허용된 준비 환경에서 다음 작업을 진행합니다.

```sh
npm ci
npm run prepare:ocr
```

준비된 Mac에서 실행만 할 때는 다운로드가 필요하지 않습니다. 무거운 글자 인식·문서 캡처 작업은 한 줄로 차례로 처리하고, AI 요청은 별도 줄에서 처리합니다.

Kordoc 4.24.71은 사용자의 비공개 보관본의 패키지를 그대로 사용합니다. 엔진의 원본 커밋은 33eea18이며 패키지 SHA-256은 72eff11b3a6f61bc5a1b2900e91e0750ce765a729498ed609b5c782761b0d34c입니다. prepare:ocr는 해당 패키지가 지정한 한국어 검출·인쇄체·손글씨 인식 모델과 사전의 SHA-256을 검증합니다. 런타임은 KORDOC_OFFLINE=1을 사용합니다.

작품·원본 캡처·근거·확정 점수는 사용자 Library/Application Support/ContestReviewDesk/desk.sqlite3에 보관합니다. 로그에 본문·이미지를 기록하지 않습니다. 로컬 파일에는 민감한 원문이 포함될 수 있으므로 회사가 허용하는 장비·저장 위치에서 사용하세요. REVIEW_DATA_DIR로 회사 지정 폴더를 설정할 수 있습니다. 프로그램은 MIP 뷰어에서 허용한 캡처를 입력받습니다. 캡처 자체에 원본 문서의 접근 권한이 자동 승계된다고 가정하지 않습니다.

회사 이름 오타(빗섬·비썸)는 글자 인식·AI 요약·엑셀 접수 어디서 왔든 저장할 때 **빗썸**으로 고칩니다(서버를 켤 때 앞서 저장된 작품도 고칩니다).

## 내보내기 · Slack 보내기

작품 화면 오른쪽 위 **내보내기**는 작품 화면처럼 **캡처 자료 · AI 요약 · AI 논리점검** 탭 세 개로 나눈 HTML 한 파일을 새 탭에 엽니다(글꼴·그림을 파일 안에 넣어 인터넷 없이 같은 모양으로 열립니다). **채점표** 탭 맨 위 **담당자에게 보내기**는 Slack에 있는 사람을 이름으로 검색해 고른 뒤, 그 HTML 파일을 Slack DM으로 보내고 누구에게 언제 보냈는지 작품에 남깁니다. 보내기를 누르면 담당자와 두 봇(idea_proposal, 평가 단추 앱 idea-review)의 그룹 DM에 HTML 파일과 **평가 답장하기** 단추가 올라갑니다. 단추와 입력 창은 Slack 서버에서 돌아가는 Deno 앱(`slack-app/`)이 처리하므로 아이디어정리가 꺼져 있어도 의견을 보낼 수 있고, 아이디어정리는 켜질 때와 1분마다 그 의견을 가져와 그 작품의 채점표 **담당자 의견**에 담습니다(사람이 그냥 쓴 글은 담지 않습니다). 설치는 `slack-app/README.md`를 따릅니다.

Slack 보내기를 쓰려면 Slack 앱(예: idea-proposal)을 만들어 봇 권한 `users:read`·`chat:write`·`files:write`·`mpim:write`·`mpim:history`(그룹 DM 열기·읽기)만 주고 워크스페이스에 설치한 뒤, **Bot User OAuth Token**(`xoxb-…`)을 `deploy/site.json`에 `"slack": { "botToken": "xoxb-…", "reviewWebhook": "…" }`로 넣습니다(평가 단추 앱 웹훅은 slack-app/README.md, 평가 단추 앱 봇은 사람 목록에서 스스로 찾습니다)(환경 변수 `SLACK_BOT_TOKEN`도 됩니다). 이벤트 구독·슬래시 명령어는 필요 없습니다. 채점표 탭에는 누구에게 언제 보냈고 답장이 왔는지 **보낸 기록** 표가 보입니다. 토큰은 서버에만 있고 화면으로 보내지 않으며, 넣은 뒤 서버를 다시 켤 필요는 없습니다(화면은 1분 안에 버튼이 켜집니다). 보안 장비가 HTTPS 인증서를 바꿔 끼우는 망에서도 되도록 start.sh·start.bat은 서버를 `node --use-system-ca`로 켜 이 컴퓨터에 등록된 인증서를 믿게 합니다(curl은 되는데 서버만 'fetch failed'가 날 때의 원인).
